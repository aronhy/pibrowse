# 15 — Установка

> Загрузки PiBrowse: [Releases](https://github.com/aronhy/pibrowse/releases). Имя файла и статус подписи смотрите в конкретном выпуске. История версий и подписей ниже относится к исходному Fury; архивы `fury-core-*` берутся из [upstream Releases](https://github.com/furyteamtop/fury-antidetect-browser/releases).
> Совместимость: настройки `FURY_*`, команды `fury-*`, имена пакетов и каталоги данных сохраняют прежние имена. Старые имена файлов ядра поддерживаются; новое ядро macOS использует `PiBrowse.app/Contents/MacOS/PiBrowse`.

Для человека, который ничего не собирал. Сборка из исходников — это
[03](03-chromium-fork.md) и README; здесь предполагается, что у вас есть
компьютер и браузер, и больше ничего.

PiBrowse — это **две загрузки**, и об этом стоит знать заранее, иначе вторая
выглядит как ошибка:

| | что это | размер |
|---|---|---|
| **PiBrowse** | приложение: профили, прокси, персоны, команда | ~12 МБ |
| **PiBrowse core** | сам браузер — форк Chromium | 103 МБ на macOS, 146 МБ на Windows |

Они разделены, потому что живут врозь. Приложение меняется еженедельно, ядро —
когда выходит новый Chromium, раз в шесть недель. Вместе они означали бы больше
ста мегабайт загрузки из-за сдвинутой кнопки. И это сохраняет подпись приложения: ядро,
записанное внутрь подписанного бандла, ломает его печать, после чего macOS
говорит, что приложение **повреждено** — и человек идёт искать битую загрузку
вместо того, чтобы искать нас.

## macOS

### 1. Приложение

Скачайте macOS `.dmg`, указанный на странице
[Releases](https://github.com/aronhy/pibrowse/releases). `арх` — это `arm64`
для любого Mac на Apple silicon (M1 и новее); если не уверены,  → «Об этом
Mac» покажет. Для Intel релизной сборки пока нет: она называлась бы `x86_64`,
и до её публикации на Intel-машине остаётся сборка из исходников.

Откройте и перетащите **PiBrowse.app** в `/Applications` — так же, как ставится
любое другое приложение на Mac.

### 2. Ядро браузера

Откройте PiBrowse. Он скажет, что сам браузер ещё не установлен, и предложит
**Скачать браузер** — нажмите. Это заберёт ядро для этой машины со страницы
Releases, около 100 МБ, один раз, и установит его. Ничего не работает по таймеру
или при старте: запрос уходит, когда вы нажали кнопку, и никогда иначе — приложение
обновляется так же, по кнопке (как это защищено — в конце страницы).

Или вручную: скачайте `fury-core-<версия>-macos-<арх>.tar.xz` из
[upstream Releases](https://github.com/furyteamtop/fury-antidetect-browser/releases), затем в
Терминале:

```bash
/Applications/PiBrowse.app/Contents/MacOS/fury-agent install-core ~/Downloads/fury-core-*.tar.xz
```

Кнопка выполняет ровно это. Команда делает три вещи, которые вручную легко
сделать неправильно: распаковывает бандл, сохраняя симлинки, из которых собран
macOS-фреймворк, снимает карантинный флаг, который поставил ваш браузер при
скачивании, и — главный шаг — **запускает браузер один раз и проверяет, что он
стартует**. Пример вывода совместимого ядра исходного проекта (legacy):

```
installed Fury 157.0.8103.39
  /Users/you/Library/Application Support/Fury/core.bundle/Fury.app/Contents/MacOS/Fury
```

Новое ядро из этих исходников PiBrowse находится по пути
`core/src/out/<target>.noindex/PiBrowse.app/Contents/MacOS/PiBrowse`. После установки
из архива ядра PiBrowse путь будет
`~/Library/Application Support/Fury/core.bundle/PiBrowse.app/Contents/MacOS/PiBrowse`.
Путь с `Fury.app` выше — пример совместимости с legacy-ядром, а не результат
новой сборки.

Спросить, что установлено, можно в любой момент:

```bash
/Applications/PiBrowse.app/Contents/MacOS/fury-agent install-core
```

### 3. Запустите

Откройте PiBrowse из «Программ». Ни аккаунта, ни регистрации, ни сервера: работает
сразу, всё остаётся на этой машине.

Командная работа — общие профили, общий пул прокси, доступ по проектам — в
**Настройки → Командный сервер**, там же создаётся аккаунт и там же лежит
инструкция по поднятию своего сервера. Укажите адрес сервера своей команды. PiBrowse не подставляет сервер исходного проекта; локальный режим можно использовать без аккаунта.

### Проверить, что скачалось

У каждого релиза есть файл `SHA256SUMS`. Скачайте его рядом с архивами и:

```bash
shasum -a 256 -c SHA256SUMS
```

Две строки `OK` означают, что файлы те самые, что были опубликованы.

### Если macOS отказывается открывать

Проверьте статус подписи и контрольные суммы в выбранном выпуске PiBrowse. Сборки исходного Fury для macOS подписывались и нотаризовались с 21.09.2026; это не подтверждает статус подписи PiBrowse. Ниже — действия для неподписанной или локальной сборки.

**«PiBrowse нельзя открыть, так как разработчик не может быть проверен».** Это
обычный результат для неподписанного приложения, и именно его следует ожидать
для *правильного* файла — прошлая версия этой страницы советовала скачать
заново, то есть отправляла в петлю без выхода. Вместо этого:

  1. Попробуйте открыть один раз и закройте диалог. Затем Системные настройки →
     Конфиденциальность и безопасность, в самом низу: рядом с *«PiBrowse» заблокирован*
     нажмите **Всё равно открыть** и подтвердите. macOS запомнит выбор для этой
     копии. (Раньше хватало правого клика → **Открыть**; начиная с macOS 15 —
     нет.)
  2. Или снимите карантинный флаг в Терминале — именно о нём этот диалог:

     ```bash
     xattr -dr com.apple.quarantine /Applications/PiBrowse.app
     ```

То же касается ядра: `fury-agent install-core` снимает флаг с того, что
распаковывает, поэтому отдельного шага для ядра здесь нет.

**«PiBrowse повреждён и не может быть открыт».** На macOS 15 и новее это та самая
формулировка для скачанного ad-hoc-подписанного приложения, то есть тот же
случай, что выше. Проверьте источник и контрольные суммы до снятия карантинного флага. Если сообщение пережило шаг с `xattr`, значит печать
сломана — внутрь `PiBrowse.app` что-то добавили или из него что-то удалили, — и
лечится это удалением и повторной распаковкой загрузки.

**Ядро, собранное самостоятельно, не запускается** с сообщением про *Team IDs*.
Это устройство подписи, а не сломанная сборка; разбор целиком —
в [tools/release/sign-core.sh](../tools/release/sign-core.sh).

## Windows

Работает с 16.08.2026 и лежит в релизах начиная с 0.1.1. Прошлая версия этого
раздела говорила «пока нет» ровно столько, сколько это было правдой: лаунчер
портировали первым, а ядро — сборку Chromium — никто не прогонял на машине с
Windows. Теперь прогнали, и `tools/verify-windows.ps1` проходит на реальной
машине 30 проверок против него. Те же две загрузки, что и на macOS.

### 1. Приложение

Скачайте установщик Windows, указанный на странице
[Releases](https://github.com/aronhy/pibrowse/releases) и
запустите. **SmartScreen будет возражать** — «Система Windows защитила ваш
компьютер» — потому что установщик не подписан, а не потому, что с ним что-то
не так. Нажмите **Подробнее**, затем **Выполнить в любом случае**.

Установщик ничего не спрашивает: ставит для текущего пользователя, в
`%LOCALAPPDATA%\PiBrowse` (старые установки: `%LOCALAPPDATA%\Fury`), и пароль администратора ему не нужен. В этой папке лежат
`fury-desktop.exe`, `fury-agent.exe` и деинсталлятор — и больше ничего.

### 2. Ядро браузера

Откройте PiBrowse и нажмите **Скачать браузер** — та же кнопка, что на macOS: она
забирает совместимое ядро; архивы исходного проекта
`fury-core-<версия>-windows-x64.tar.xz` доступны в [upstream Releases](https://github.com/furyteamtop/fury-antidetect-browser/releases), около 150 МБ,
один раз, и устанавливает. Или вручную — скачайте этот файл оттуда же и в
PowerShell:

```powershell
& "$env:LOCALAPPDATA\PiBrowse\fury-agent.exe" install-core "$env:USERPROFILE\Downloads\fury-core-<версия>-windows-x64.tar.xz"
```

На Windows шаг установки читает версию из самого исполняемого файла, а не
запускает его: `chrome.exe --version` запускает браузер и никогда не
завершается.

### 3. Запустите

Откройте PiBrowse из меню «Пуск». Всё, что раздел про macOS говорит об учётных
записях, верно и здесь: их нет, пока вам не понадобится команда.

**Widevine** — Netflix, Spotify и прочие сайты с DRM — в загрузке нет, потому
что его нельзя распространять. Агент берёт его из Chrome, уже установленного на
машине; машина без Chrome получает рабочий браузер без DRM, и сайт, который это
проверяет, заметит.

## Linux

Не цель. Это решение, а не пробел, и сказать это стоит прямо: прежняя версия
этой страницы обещала релиз под Linux.

Rust под Linux по-прежнему компилируется — там работает CI, и контрибьюторы
могут гонять тесты, — но готовой сборки, конфигурации сборки ядра и планов нет.
Две платформы, которые тестируются, стоят больше трёх, где одна — догадка.

## Где что лежит

Всё, чем владеет PiBrowse, под одной директорией, поэтому «сделать бэкап» и «удалить
всё» — по одной операции:

```
~/Library/Application Support/Fury/
  fury.db          профили, прокси, персоны, проекты
  profiles/        данные браузера по профилям — куки, вкладки, закладки
  core.bundle/     установленный браузер (пакет, чтобы в поиске
                   был один PiBrowse, а не два)
  dock.noindex/    macOS: клон браузера на каждый профиль с его именем
                   для Dock; клоны APFS, реального места не занимают
```

На Windows та же директория — `%APPDATA%\Fury`, Roaming, а не Local, и это
намеренно: на машине в домене она следует за пользователем, а потерять базу на
другой машине выглядело бы как потеря данных, а не как промах кэша.

`FURY_HOME` переносит это куда угодно — на внешний диск или в шифрованный том.

Удалить PiBrowse полностью: стереть эту директорию и `/Applications/PiBrowse.app` — на
Windows эту директорию и PiBrowse из «Параметры → Приложения».
Больше ничего никуда не пишется, и ничего не остаётся ни на одном сервере,
который вы не подняли сами.

## Обновление

С 0.3.0 на полосе «Вышла новая версия» есть кнопка **Обновить**: PiBrowse скачает
новую версию, проверит подпись, установит её и перезапустится. Профили, прокси и
настройки сохранятся. Сначала закройте открытые профили, кнопка подскажет, если
они открыты. До 0.3.0 или если хочется вручную: скачайте новый `.dmg` и перетащите приложение поверх старого; на Windows —
запустите новый установщик поверх старого. Для нового ядра снова нажмите
**Скачать браузер** или запустите `install-core` с новым архивом — в обоих
случаях проверяется, что новое ядро стартует, прежде чем заменить имеющееся, так
что битая загрузка оставит вас с рабочим браузером, а не без браузера. Заметки к
релизу говорят, когда ядро не менялось, — тогда приложение остаётся единственной
загрузкой.

## Как устроена защита кнопки «Обновить»

Апдейтер — это канал в анти-детект браузер, поэтому этот сделан не шире, чем
человек, который сам скачал установщик:

- **Само ничего не ставится.** Проверка только показывает полосу; установка
  начинается, когда вы нажали кнопку, и никогда по расписанию.
- **Ставится только сборка с подписью ключа проекта.** В каждом релизе есть
  `latest.json` и подпись minisign для сборки каждой системы; приложение
  сверяет её с открытым ключом, с которым было собрано, до того как что-либо
  остановить. Изменённый файл, другой ключ или релиз без подписи отклоняются, и
  кнопка открывает ссылку на загрузку. Закрытый ключ лежит на машине, где
  собираются релизы, и больше нигде.
- **Открытые профили не прерываются.** Пока хоть один открыт, кнопка
  отказывается; фоновая служба останавливается только после того, как
  загрузка проверена.
- Загрузка идёт с GitHub через подключение этой машины, как и проверка, а не
  через прокси профиля.
