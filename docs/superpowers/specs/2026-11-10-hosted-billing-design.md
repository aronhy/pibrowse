# Fury 托管团队订阅

## 范围

开源 Fury 继续支持本地使用和免费自建。我们托管的团队服务按组织收订阅费，首版只接 Stripe 的一个月付价格。金额和币种由支付平台的价格配置决定，代码不写死。现有团队账号、成员关系和权限沿用 Fury。

## 接入方式

采用已选择的方案，把 Open SaaS 的结账、客户门户和签名回调流程移植到 Fury 的 Rust 服务。Open SaaS 模板默认按用户计费，移植后以 Fury 的组织 ID 为唯一计费归属。若独立部署 Wasp 模板，则需要再维护一套应用、账号映射和订阅同步，因此本版采用移植方案。Open SaaS 中实际移植的代码保留 MIT 声明。

参考 Open SaaS 提交 [5f5dd77](https://github.com/wasp-lang/open-saas/tree/5f5dd77403b97952f6b3c3ff2131d1e9eea03f1f/template/app/src/payment/stripe)。

## 用户流程与访问规则

- 组织成员可以查看本组织的订阅状态。组织 Owner 可以发起 Stripe Checkout 或打开 Customer Portal 管理订阅、续费和发票。桌面端复用现有 Tauri 请求通道，用系统浏览器打开支付页面。
- 服务端校验组织角色和归属，价格、HTTPS 回跳页、支付客户标识由服务端配置或数据决定。用户结账后在桌面端刷新状态，首版沿用普通网页回跳。最终开通以服务端确认的 Stripe 状态为准。
- 有效订阅允许新开托管环境，以及创建、克隆、恢复环境和邀请新成员。取消自动续费的订阅在已付周期内继续有效。首版不提供试用或欠费宽限，未付费或已失效的组织可以登录、查看现有记录、访问现有导出功能和续费。
- 环境操作先走现有权限检查，再检查订阅。跨组织共享按环境所属组织的订阅判断。订阅失效时禁止获取新环境锁，现有会话仍可心跳、保存和解锁，避免丢数据。
- 托管计费通过显式服务端配置开启，缺失所需配置时拒绝以计费模式启动。默认自建和 Solo 使用不依赖支付平台。既有托管组织接入前需要核对订阅状态后再启用。

## 账单状态与交付

- PostgreSQL 记录组织与 Stripe Customer 的唯一映射、当前订阅、已付周期截止时间和回调事件 ID。开通以对应价格的已支付账单覆盖期和订阅状态共同判定。重复点击结账不能创建多个可完成的订阅会话。已有订阅的 Owner 通过账单门户管理。
- 用原始请求体验证 Stripe 签名，校验测试或生产模式、已绑定的客户和配置价格。按组织串行获取 Stripe 当前订阅状态，处理重复或乱序回调，状态更新和事件去重一起提交，失败可以重试。
- 本阶段实现并验证测试模式。正式收费前需要已配置的商户、产品价格、生产回调、账单门户和对应版本源码入口。生产环境使用受现有行级权限约束的数据库角色。

## 验收

- 关闭计费时，自建模式的注册、成员管理和环境操作按原流程工作。
- 仅 Owner 能创建 Checkout 和账单门户会话。使用其他组织、客户或价格标识无法获得访问。
- 验证签名错误、重复或乱序回调、支付成功、取消续费、周期结束和重新订阅。重点覆盖单个工作区的并发结账和跨组织共享。
- 失效组织无法开新环境，仍可正常关闭已打开环境、保存数据和续费。
- 先跑 Rust 服务端与 PostgreSQL 集成测试、桌面类型检查和模拟支付。具备测试账户配置后，再验证真实测试结账、回调和恢复访问。实际扣款和生产发布单独验收。
